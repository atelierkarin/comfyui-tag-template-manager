## 実装済み

### Core

- テンプレートの JSON スキーマ検証、個別ファイルの保存・読み込み・一覧・削除。新規保存時の ID 衝突は拒否する。
- ブロックの既定状態、プリセット、個別切替。排他グループは Positive／Negative ごとに判定する。
- チャンネル別の結合、余分な区切りや平文の空白整理、限定的な重複除去、平文タグの完全一致による一時的な除外。複雑な構文は保守的に扱う。

### Nodes / Editor

- `Tag Template`：選択 UI、`TAG_BUNDLE` と Positive／Negative の `STRING` 出力。プリセットなしでもブロックの既定状態を使う。
- `Tag Main`：最大 8 個の Bundle と自由入力を接続し、選択したチャンネルを単一の `STRING` として出力。`exclude` と手動更新のプレビューを提供する。
- テンプレート編集画面：一覧・検索・作成・保存・複製・削除、ブロックの編集と折りたたみ、プリセットの編集。ブロック構成の変更後は、残った選択を維持しつつ追加ブロックに既定状態を適用する。
- テンプレートはユーザーデータ側の `default/tag_templates/` に保存。ノードごとの選択状態はワークフローに保存する。
- 初期の 2 出力 Main はユーザーの確認後に削除済み。現在の `Tag Main` を使用する。

## 次の候補：Stability

以下は全体設計にある残課題と、次の作業に向けた**優先順の提案**。着手範囲や仕様は次スレッドで決める。

1. **インポート／エクスポート**：テンプレート JSON の持ち出しと取り込み、スキーマ検証、既存 ID 衝突時の確認。上書きを暗黙で行わない。単体テストと画面操作の確認が必要。
2. **バックアップと破損復旧**：保存・削除・読み込み失敗時の利用者向け対応を整理。元データを不用意に上書きせず、復旧手順とテストを用意する。
3. **Snapshot モード**：テンプレート内容と選択状態をワークフローに保存し、外部 JSON の変更や欠損に左右されない再現性を設計する。既存 Live ワークフローの互換性、保存データ形式のバージョン、Live との切り替えと表示が要検討。
4. **同時編集の競合検出**：複数画面や外部ツールで同じテンプレートを編集した際、変更を黙って上書きしない仕組みと回復方法を設計する。
5. **エラー表示と統合検証**：欠損・破損・選択不整合、再読み込み後の復元、プレビューと実出力、テンプレート更新と実行キャッシュを実機で再確認する。

現在の Live キャッシュ対策は `Tag Template` を毎回再実行させる方式で実装済み。最適化は必須ではなく、変更する場合はファイル更新・削除・破損・競合時に古い結果を返さないことを検証する。

## その他の制限・将来候補

- マルチユーザーモードは意図的に拒否している。対応する場合は HTTP リクエストとノード実行で利用者を安全に対応付け、データ分離を検証する必要がある。
- プレビューは手動更新。`Tag Template` と通常の Reroute からの接続が対象で、外部ノードに接続された自由入力ウィジェットなどは評価できない。
- 除外は平文タグの大文字小文字を区別しない完全一致。例：`ribbon` は `hair ribbon` や `(ribbon:1.2)` を除外しない。複雑な構文の意味解析は対象外。
- 自動タグ提案、Tagger 連携、クラウド同期などは全体設計の初期対象外。ComfyUI Manager 対応も将来候補であり、具体的な登録・公開フローは未設計。CI はテストのみで、デプロイや公開を行わない。
