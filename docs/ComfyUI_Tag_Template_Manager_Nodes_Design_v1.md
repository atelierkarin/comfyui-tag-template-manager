# ComfyUI Tag Template Manager — Phase 2 Nodes 設計書

作成日：2026-11-12  
位置づけ：[全体設計](ComfyUI_Tag_Template_Manager_Design_v1.md) と [Core 設計](ComfyUI_Tag_Template_Manager_Core_Design_v1.md) を継承し、第2段階の実装方針を具体化する。未確定の詳細は本書の提案とし、実装時に対象環境で検証する。

## 1. 目的と対象範囲

Core のテンプレートを ComfyUI のワークフローから選択し、複数のテンプレートと自由入力を組み合わせ、Positive / Negative の文字列を既存ノードへ接続できるようにする。テンプレート選択やブロックの状態はノードごとに独立し、ワークフローの保存・再読み込みで復元する。

この段階では次を扱う。

- Tag Template Node と Tag Main Node、および最低限の選択 UI。
- テンプレート一覧・取得と結合プレビューに必要な読み取り用 HTTP API。
- ワークフロー状態の保存、復元、テンプレート更新時の不一致検出。
- テンプレート変更を実行結果へ反映するためのキャッシュ対策。
- Python 単体・結合テストと、対象 ComfyUI 上での手動操作確認。

テンプレート作成・編集・削除の画面や書き込み API、インポート／エクスポート、Snapshot、バックアップ・破損復旧は後続段階とする。この段階の動作確認には Core の `TemplateStore` 等で事前に作成した有効な JSON を用いる。タグのプレビューも表示するが、画像生成結果のプレビューではない。

## 2. 現環境で確認したことと制約

- 対象は現在の ComfyUI 0.22.0、ポータブル版 Python 3.13.12。Python 要件は 3.10 以上。
- インストール済み `nodes.py` は `NODE_CLASS_MAPPINGS` と `WEB_DIRECTORY` を読み込み、`execution.py` は従来ノードの `IS_CHANGED` を参照する。実際の引数と再実行挙動は実装時の統合テストで確認する。
- `folder_paths.get_user_directory()` はユーザーデータの基点を返す。ComfyUI の `UserManager` はリクエストごとにユーザーを解決する。一方、通常のノード実行で同じ利用者の識別子を安全に取得できるかは未確認。
- この段階は **単一ユーザーモードのみ対応**とする。標準の `default` ユーザー領域内の `tag_templates/` を使用する。`--user-directory` による基点の変更は尊重する。マルチユーザーモードでは読み取り API とノード実行を明確なエラーで拒否し、他人のライブラリや共有領域へフォールバックしない。
- `app.registerExtension` の利用例はローカルに存在するが、選択 UI とウィジェットの保存・実行入力への受け渡しは対象フロントエンドで未検証。安定する方式を実機で確認し、非公開 DOM の書き換えに依存しない。

## 3. 方式とデータの流れ

| 方式 | 利点と制約 | 判断 |
| --- | --- | --- |
| Bundle にテンプレートと選択状態を保持し、Main で Core の結合処理を実行 | 複数ブロックやテンプレートを通じて重複除去でき、Core とプレビューを共通化できる | 採用案 |
| Template Node で先に各チャンネルを文字列化する | 接続値は小さいが、複雑な断片と平文断片の境界が失われ、Core の安全な重複除去を再現できない | 採用しない |

`Tag Template Node → TAG_BUNDLE → Tag Main Node → STRING × 2` とする。Bundle は Python 内部で使う専用型であり、テンプレート ID、検証済みテンプレート内容、完全なブロック選択状態を含む。Core の辞書を直接共有・変更せず、ノード間では独立したデータとして渡す。ワークフロー JSON に Bundle 本体を保存せず、後述のノード入力状態を保存する。

Main は接続ポート順に Bundle を並べ、`services.prompt_builder.build_prompts` へテンプレート・選択の組を渡す。これにより Positive / Negative の分離、ブロック順、自由入力の追加、重複除去の規則を Core と共有する。Core の振る舞いが設計書と一致しない箇所を見つけた場合は、回帰テストを追加して修正する。

## 4. Tag Template Node

- カテゴリーは `Tag Template Manager`。初期入力はテンプレート選択、プリセット選択、ブロック一覧の ON / OFF、一覧更新。出力は `TAG_BUNDLE` 一つ。
- テンプレート選択後に既定状態を生成する。プリセット適用は選択状態を置き換え、以後の個別操作を許可する。同じ排他グループの別ブロックを ON にした場合、以前の ON を解除する。グループ内をすべて OFF にすることもできる。
- 画面には表示名を使用し、保存・参照には ID を使用する。同じ表示名があっても ID で区別できるようにする。テンプレート未選択とライブラリ空は区別できる表示にし、未選択で実行した場合は理由を示して失敗する。
- この段階では Editor がないため Edit ボタンは表示しない。更新操作は一覧と選択中テンプレートを再取得し、状態不一致があれば §6 の方針に従う。
- 実行時はサーバーの最新版を取得して検証し、送られた選択状態を照合する。存在しないテンプレート、破損 JSON、選択不一致を空 Bundle に変換しない。

## 5. Tag Main Node

- 固定の任意入力 `bundle_1`〜`bundle_8`、自由入力 Positive / Negative、重複除去 ON / OFF（初期 OFF）を持つ。固定ポートを採用し、動的ポートは後続の拡張候補とする。
- 未接続ポートを飛ばして番号順に処理する。Bundle がゼロでも自由入力のみで使用できる。出力は `positive: STRING` と `negative: STRING`、この順序で CLIP Text Encode に接続できる。
- 読み取り専用の結合プレビューを表示する。Core を使うサーバー側の共通処理をプレビューと実行の両方から呼び出し、別々の JavaScript 結合ロジックを持たない。
- 未実行の編集状態でもプレビュー API へ現在の接続・選択・自由入力を明示的に送り、最新の結果を取得する。非同期応答の逆転を防ぎ、古い応答を表示しない。API 失敗時はエラーと表示が無効であることを示す。
- プレビュー時と実行時の入力・テンプレート内容が同じ場合、結果は完全一致する。表示後にファイルが変更された場合はプレビューが古い可能性を示し、更新または実行後に再取得する。プレビュー結果自体を実行入力として信用しない。

## 6. 状態の保存とテンプレート更新

Template Node の保存対象は、バージョン付きのノード状態、テンプレート ID、最後に適用したプリセット ID（任意）、すべての Block ID と真偽値の対応。最終的なブロック状態を正とし、プリセット ID は表示用の履歴として扱う。自由入力や重複除去は Main Node の通常入力として保存する。

状態はフロントエンドの見た目だけでなく、ワークフロー保存と実行 API の両方に渡るシリアライズ可能な入力として保持する。ComfyUI 0.22.0 でこれを保証するウィジェットの実装方式を検証する。新規ノードと復元ノードを区別し、復元済み状態をテンプレート取得後の既定値で上書きしない。

Live モードでは実行時の最新テンプレートを使う。Block ID が一致しない、または更新により選択が排他違反になった場合は、現在の Core と同様に実行を停止し、欠落・追加された ID や矛盾を示す。ユーザーが明示的に「既定状態にリセット」またはプリセットを再適用したときのみ状態を置き換える。自動移行や不明な ID の黙った削除はしない。テンプレート ID が見つからない場合も同様に復元状態を保持し、修正できるエラーを表示する。

古い状態形式の未知バージョンや不正な JSON も黙って初期化しない。今後形式を変更する際はバージョンごとの移行を用意する。Snapshot はこの段階では実装しない。

## 7. 読み取り API と保存先

プラグイン固有の名前空間に、テンプレート一覧、ID 指定の取得、結合プレビューの API を設ける。HTTP メソッド、応答形式とエラー形式は実装時に固定し、テストと併せて文書化する。API は ComfyUI のユーザー解決・単一ユーザー制約を通してストアを生成し、クライアントからファイルパスを受け取らない。ID は Core の検証を使用する。

一覧は ID・表示名など選択に必要な情報を返し、取得は検証済みテンプレートを返す。プレビューは入力の ID・選択状態をサーバー側で検証し、同じストアから最新テンプレートを読み込んで Core の結合関数を実行する。壊れたライブラリや選択エラーは HTTP エラーと理由を返し、空配列・空文字列に置き換えない。書き込み・削除のエンドポイントは設けない。

## 8. キャッシュと整合性

Template Node の再実行判定には、選択されたテンプレートの**内容**の変更を含める。`IS_CHANGED` 等の対象バージョンで有効な仕組みを使い、更新・削除・破損を検出する。更新時刻だけに依存しない。欠損や読み取り失敗時にも古い正常結果を再利用せず、実行エラーとなるよう検証する。

ファイルの読み込みとハッシュ計算の間に変更が起こり得るため、実行が使用する内容と判定値の関係を明示的にテストする。ComfyUI の判定とノード実行が別時点になる制約は残るため、更新競合時には誤って古いキャッシュを返さない仕組みを実装時に確認する。保証できない場合は、安全側として Template Node を毎回再実行する方式に切り替える。Main Node は入力 Bundle の変更を受けて再実行されることを確認する。

## 9. エラーと利用者への表示

未選択、テンプレート不存在、破損、ブロック状態不一致、ライブラリ読み取り失敗、プレビュー失敗、非対応のマルチユーザーモードを区別して表示する。対象のテンプレート ID と修正方法を示し、必要に応じてサーバーログに詳細を残す。生の例外やローカル絶対パスを常に画面へ露出する必要はない。エラー時は保存済み選択を保持し、別のテンプレートを自動選択しない。

## 10. 検証と完了条件

自動テストでは既存 Core テストに加え、ノード・API の正常系、空ライブラリ、欠損・破損、状態不一致、排他、2 ノードの独立性、固定ポート順、重複除去、プレビューと実行の一致、マルチユーザーモードの拒否を検証する。テンプレート内容の更新・削除・破損後に古いキャッシュが使われないことを ComfyUI の実行経路で確認する。

対象 ComfyUI 上で次を手動確認する。

1. 有効な JSON を用意し、ノードが読み込まれること、選択・プリセット・排他が操作できること。
2. 同じテンプレートを選ぶ 2 ノードで異なる選択を保存し、ワークフローを再読み込みして独立状態が復元すること。
3. 2 個以上の Bundle と自由入力を Main に接続し、プレビュー、実出力、CLIP Text Encode 接続が一致すること。
4. 実行後にテンプレート本文を変更して再実行し、変更が出力に反映されること。ID の追加・削除・破損・欠損も検出されること。
5. 設定されたユーザーディレクトリの `default/tag_templates/` を使用すること、およびマルチユーザーモードで安全に拒否すること。

上記の自動テストと手動確認を完了条件とする。実機確認できない項目は未検証として報告し、完了と見なさない。

## 11. 後続段階への引き継ぎ

- **Editor**：テンプレート管理画面と書き込み API、削除確認、インポート衝突の取り扱い。
- **Stability**：Snapshot、バックアップと破損復旧、状態移行、実行・プレビュー間の競合改善、必要に応じたマルチユーザー対応。
- **拡張候補**：動的ポート、8 口を超える接続方法。固定ポートや保存済みワークフローとの互換性を維持して設計する。
