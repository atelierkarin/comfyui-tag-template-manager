# v0.4.0 Tag Main・入力集約 設計案

作成日：2026-11-20

状態：レビュー用提案。名称などの詳細は未確定。

## 背景と目的

実際の利用で、`Tag Main` の８個の Bundle 入力がノードを大きくし、テキストを Conditioning にするために別の `CLIP Text Encode` も必要になっている。接続を整理し、組み立てたテキストとそれをエンコードした Conditioning を同じノードから取得できるようにする。

複数テンプレートを使うワークフローで Main 側の Bundle 入力を１つにでき、別のエンコードノードなしで生成に使えることを目指す。既存 `Tag Main` の入力変更に伴う接続の手動移行を許容する。

対象は単一ユーザーモード。複雑なプロンプト構文の意味解析、マルチユーザー対応、既存ワークフローの自動書き換えは対象外。

## 現状と方式の比較

現行 `Tag Template` はノードごとに選択を持ち、Live または Snapshot から `TAG_BUNDLE` を出力する。現行 `Tag Main` は最大８個の Bundle を入力番号順に結合し、チャンネルを選んで１本の `STRING` を返す。自由入力、重複除去、除外と手動プレビューがある。Positive と Negative の両方が必要なら Main を２つ使う。

1. **Bundler 方式**：既存 Template の Bundle を新しい Bundler に集め、エンコード対応 Main がその集合を１入力で受け取る。個別選択と Snapshot を活用でき、現行の作業方法から移行しやすい。一方、Bundler と配線は残る。
2. **Main で Template・Preset を直接選択**：Main 上で複数のテンプレートと各プリセットを選ぶ。Template ノードと配線を減らせるが、プリセット以外の個別ブロック選択はできず、状態保存、Live/Snapshot、削除や変更への追従を新たに設計する必要がある。

両方式を提供する方針とする。v0.4.0 では 1 と Conditioning 出力を先に実装し、2 は次バージョンに向けて集中的に設計・実装する提案とする。直接選択には Main 独自の複数選択状態、ライブラリ変更への追従、Snapshot とエラー処理、保存・再読み込み、プレビューの設計と検証が必要で、Bundler の追加に比べて作業範囲が大きいため。次バージョンの機能として確定済み・実装済みとは扱わない。

## 提案するノード構成

`Tag Template` → `Tag Template Bundler` → `Tag Main (Encode)` → text / conditioning。モデルの CLIP 出力を Main の必須 `clip` 入力につなぐ。

- Bundler は既存 `TAG_BUNDLE` を番号付きの任意入力で最大８個受け、順序を保った新しい専用型 `TAG_BUNDLE_LIST` を１つ出力する。空入力は空の集合とし、欠番は飛ばす。同じ Template を複数接続した場合も入力ごとに扱う。連結や動的入力は本案の対象外。
- 新 Main は必須 `clip`、任意 `bundles`、既存と同じ `channel`、`text`、`deduplicate`、`exclude` を持つ。Bundler 未接続でも自由入力のみで実行できる。集合から選択チャンネルを組み立て、既存の `compose_single` と同じ順序・除外・重複除去を適用する。
- 出力は `text: STRING`、`conditioning: CONDITIONING` の順。両方とも同一の最終テキストに基づく。空文字も通常のテキストとしてエンコードし、独自の空 Conditioning を作らない。エンコード失敗は明確に伝播する。
- エンコードは対象 ComfyUI の標準 `CLIP Text Encode` と同じ CLIP のインターフェースと戻り値を使い、トークン化、スケジュールやメタデータを独自に解釈しない。同一 CLIP・テキストに対して標準ノードと結果の構造と値が一致することを実機で検証する。
- Main は現行同様に１チャンネルを扱う。Positive と Negative を得るには同じ Bundler を２つの Main に接続し、各チャンネルを選ぶ。排他グループは既存どおり各 Template 内・各チャンネルで適用し、別 Template 間に新たな排他を導入しない。

## 互換性と状態

既存 `TagTemplateManagerTemplate` と `TagTemplateManagerSingleMain` の型識別子と出力順を維持する。テキスト専用の既存 Main も８個の Bundle 入力を Bundler の `bundles` 入力に変更する。旧ワークフローの接続は自動移行せず、Bundler を追加して接続し直す必要がある。新 Main と Bundler には新しい型識別子を与える。

Template の ID、プリセット ID、バージョン付き状態、Live / Snapshot の意味を変えない。Bundler は実行時の Bundle を順序付きで渡すだけで、選択やテンプレートを別途保存しない。選択は引き続き Template ノードごとに独立する。Live の更新・欠損・破損時に古い結果を返さず、Snapshot は保存済み内容を使う。新ノードは単一ユーザー制限を守る。旧版のプラグインでは新ノードを含むワークフローを利用できない。

## プレビューとエラー

新 Main の手動プレビューは Bundler の各接続を入力順にたどり、Template と通常の Reroute を解決して既存のサーバー側プロンプト構築を使う。プレビューはテキストのみで、CLIP や Conditioning は評価しない。未接続の Bundler は空集合として扱う。未対応の接続元、循環、選択なし、欠損・破損したテンプレートは明示的なエラーとし、空結果や古いプレビューで成功したように見せない。外部接続された自由入力等を評価できない既存の制限は維持する。

入力順、欠番、重複接続、空集合、Live / Snapshot をプレビューと実行で一致させる。途中で更新されたプレビュー応答が新しい結果を上書きしない既存の保護も維持する。

## 次バージョン：Main からの直接選択

次段階では `Select Template Preset` から複数の Template とそれぞれの Preset を選び、Template ノードや Bundler を経由せず Main で合成できる方式を目指す。この方式では Preset のみを選択可能とし、個別ブロックの切り替えは提供しない。Bundler 方式は引き続き利用できるようにする。

直接選択はまだ詳細設計を要する。選択する組の順序と重複、Template／Preset の削除・変更時のエラー、Live と Snapshot の扱い、ワークフローごとの選択状態と保存形式、プレビューと実行の一致を決める。Bundler と直接選択を同一 Main で併用可能にするか、別ノードまたは切り替え式にするかも、その際に操作と互換性を比較して決定する。併用する場合は合成順序と選択状態の扱いを明示する。

直接選択にも既存の共有プロンプト構築、チャンネルごとの排他、単一ユーザー制限、欠損・破損時の明確なエラーを適用する。Preset の変更を既存ワークフローにどう反映するかは Live / Snapshot の設計と一緒に決定し、暗黙に空出力へ置き換えない。
