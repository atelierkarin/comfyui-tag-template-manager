# v0.5.0 Main での Template・Preset 直接選択 設計案

作成日：2026-11-22
状態：レビュー用提案。利用者の承認前であり、実装仕様として確定していない。

## 目的と範囲

`Tag Main` と `Tag Main (Encode)` から複数の Template とそれぞれの Preset を直接選び、Template ノードや Bundler の配線なしでプロンプトを組み立てる。既存の Bundler 方式も使えるようにし、両 Main の型識別子・既存出力の順序を維持する。単一ユーザーモードを前提とする。

直接選択は Preset 単位とし、個別ブロックの切り替えや Preset のない Template の既定状態の選択は対象外とする。個別選択が必要な場合は既存の Template ノードを使う。テンプレートの保存形式、編集機能、マルチユーザー対応、プロンプト構文の意味解析、旧ワークフローの自動書き換えは対象外。

## 方式の比較と提案

1. **既存 Main に直接選択を追加して Bundler と併用する（推奨）**：既存の Main と出力をそのまま使え、配線済みの入力に直接選択を追加できる。合成順と状態の保存・キャッシュを定義する必要がある。
2. **既存 Main に入力方式の切り替えを追加する**：一度に使う方式が明確だが、両方式を組み合わせられず、切り替え時に保持された選択の扱いが複雑になる。
3. **直接選択専用 Main を新設する**：既存ノードの変更は小さいが、テキスト専用とエンコード対応の両方で機能が重複し、方式間の併用にも別の仕組みが必要となる。

本案は 1 を提案する。以下は利用者が選択・承認する前の設計上の提案であり、合意済みの決定ではない。

## 操作と合成順

両 Main に直接選択の一覧を設ける。行を追加し、Template とその Preset を選択する。行の削除と上下移動を可能にし、同じ Template や同じ Template・Preset の組も複数回選べる。表示名が重複する場合は ID 等で識別できるようにする。選択は Main ごとに独立し、Positive と Negative を別 Main で使う場合もそれぞれ設定する。

合成順は **直接選択の一覧順 → 接続された Bundler の入力順 → Main の自由入力** とする。同一の組も各行で評価し、重複除去が有効な場合のみ既存ルールで結果を整理する。排他グループは各 Template の各チャンネル内で適用し、行や Template 間には拡張しない。`channel`、`exclude`、`deduplicate` と Conditioning は既存の共有処理と同じ意味を保つ。

新規 Main の一覧は空で、従来どおり Bundler や自由入力だけでも実行できる。追加途中の未選択行は完了するか削除するまで実行・プレビューで明示的なエラーとし、黙って無視しない。選択行は最大８件とする提案とし、Bundler の最大８件とは別枠とする。上限は UI・実行・プレビューで同一に検証する。

## Live と Snapshot

各行で Live または Snapshot を選択し、混在を許す。初期値は Live とする。

- **Live**：Template ID と Preset ID を保存し、実行・プレビュー時に現在の Template と同じ ID の Preset を読み込む。Preset の有効ブロックやタグの編集は次回から反映する。名称変更は ID が同じなら選択を維持する。追加ブロックは Preset に含まれない限り無効とする。
- **Snapshot**：明示的な操作で取得した検証済み Template 全体と Preset ID を行に保存し、その保存内容から Preset を解決する。元のライブラリが変更・削除されても結果を維持する。Snapshot の更新や Live への切り替えは結果が変わり得ることを表示し、確認後に行う。Snapshot 作成・更新時は現在のライブラリを取得して検証し、失敗時は既存状態を保持する。

どちらも Preset の `enabled_block_ids` から全ブロックの真偽値を生成し、既存の Bundle 構築とプロンプト処理を共有する。Template ノードの状態では Preset 適用後にブロックを個別変更できるため、その状態を直接選択の Live 参照と同一視しない。

Live の Template または Preset の欠損、破損、無効なデータ、Snapshot の不正、未対応の状態バージョンは、対象行を特定できるエラーとする。削除された Preset を既定状態や別の Preset に置き換えない。ユーザーが行を修正・削除するか、ライブラリを復元する。名前は表示用であり解決には ID を使う。

## 保存形式と互換性

Main のワークフローにバージョン付きの直接選択状態を保存する。例：

```json
{"version":1,"items":[
  {"mode":"live","template_id":"character","preset_id":"casual"},
  {"mode":"snapshot","template_id":"style","preset_id":"soft","template":{"schema_version":1,"id":"style","name":"Style","category":"","description":"","blocks":[],"presets":[{"id":"soft","name":"Soft","enabled_block_ids":[]}]}}
]}
```

配列順を合成順とし、各行の必須フィールド・ID・上限・Snapshot の Template ID 一致と Preset の存在をサーバー側で厳密に検証する。Snapshot は既存テンプレートスキーマを検証する。状態の JSON は既存 Template 状態とは別の形式として扱い、重複キーや不正な値を拒否する。UI 表示用の一時情報は実行状態に混ぜない。

旧ワークフローに直接選択状態がない場合は空一覧として扱い、既存の Bundler、入力、出力、ウィジェット値を維持する。ComfyUI の保存・復元方式に合わせて状態を追加し、旧ワークフローの読み込み時に他のウィジェット値がずれないことを実機とテストで確認する。旧版プラグインで v0.5.0 の直接選択を含むワークフローの再現は保証しない。Template ノード自体の状態形式は変更しない。

## 実行、プレビュー、エラー

両 Main の実行時に直接選択を共有サービスで Bundle に解決し、接続 Bundle の前に渡す。既存の `compose_single` と共有プロンプトビルダーを使用し、Encode はその最終文字列を標準 CLIP と同じ経路で処理する。Live の外部ファイル変更・削除・破損を見逃さないよう、直接選択を持つ Main は再実行を要求する。安全性を優先し、全 Main を毎回再実行する実装も許容する。単一ユーザー制限は空一覧の場合も維持する。

手動プレビューは同じ直接選択解決サービスと合成順を使用し、Bundler 側は現行どおり Template と通常の Reroute をたどる。現行 API の８状態上限は Bundler 側として維持し、直接選択の最大８行を別に検証する。既存クライアントとの互換性を保つため、既存リクエストは直接選択なしとして受け付け、拡張フィールドは厳密に検証する。CLIP は評価せず、外部接続された `channel`、`text`、`deduplicate`、`exclude` は現行どおりプレビュー不可とする。

プレビュー開始時の状態と応答を対応付け、編集中や後続要求の古い応答が現在の結果を上書きしないようにする。エラー時は古い成功結果を消して理由を表示する。ライブラリの選択肢取得の競合も同様に防ぎ、失敗で保存済みの行を消さない。プレビュー後にライブラリが変更された場合は実行結果が変わり得るため、手動更新が必要であることを表示する。

## 検証と完了条件

- 直接選択の空・未完了・上限・順序変更・重複、両チャンネル、自由入力、Bundler との併用、除外・重複除去を確認し、実行とプレビューの文字列を比較する。
- Live の Preset／タグ変更、Template／Preset の削除、破損、復元、追加ブロック、および Snapshot の作成・更新・切り替え・元データ削除を確認する。キャッシュによって古い結果や成功が返らないことを確認する。
- 複数 Main の独立性、旧・新ワークフローの保存／再読込、既存の接続・ウィジェット・出力順、状態の不正・未知バージョンを検証する。両 Main のプレビュー、Encode と標準 CLIP の一致、単一ユーザー制限も確認する。
- Python と JavaScript の所定テストを実行し、対象 ComfyUI の実ブラウザーでノード作成、選択、並べ替え、保存／再読込、プレビューと生成を確認する。実機で未確認の項目は報告する。ユーザーの稼働中のインストールやデータを無断で変更しない。
- 実装時に日本語・英語 README と変更履歴を整合させ、Live と Snapshot、制限、互換性を説明する。

## レビューして決める事項

1. 既存 Main での併用方式と、直接選択 → Bundler → 自由入力の順序。
2. 各行で Live／Snapshot を選べること、および Live が Preset の編集を追従すること。
3. 直接選択の８件上限、同一の組の重複、Preset がない Template を対象外とすること。
4. Positive／Negative の Main ごとに直接選択を設定する操作でよいか。
