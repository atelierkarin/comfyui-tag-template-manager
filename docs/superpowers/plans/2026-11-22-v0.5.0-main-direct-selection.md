# v0.5.0 Main Direct Selection Implementation Plan

> Execute inline with test-first changes and verify the complete suite.

**Goal:** Select ordered Template/Preset pairs in either Main alongside Bundler input.

**Architecture:** A versioned optional Main widget carries ordered Live references or validated Snapshot templates. A shared service resolves these to bundles for execution and preview; the frontend edits the same state and guards asynchronous responses.

**Tech Stack:** Python 3.10+, JavaScript, ComfyUI, aiohttp, unittest and Node.js.

**Spec:** `docs/superpowers/specs/2026-11-22-v0.5.0-main-direct-selection-design.md`

## Global Constraints

Preserve node identifiers, output order, existing widget values and legacy preview requests; reject multi-user mode; never silently replace invalid selections; retain shared prompt processing and current data storage.

## Review Focus

- Old workflows lack the new widget: empty default must preserve behavior.
- Library edits, deletion and corruption must invalidate cached Live output.
- Snapshot content must remain usable without the library and reject mismatched IDs.
- Delayed UI responses must not overwrite newer selection or preview state.
- Both direct and Bundler limits and their relative ordering must match preview and execution.

## Tasks

1. **Shared resolution and execution** (`services/node_service.py`, `nodes.py`, `tests/test_nodes.py`): test ordered Live and Snapshot resolution, errors, duplicate and length limits; implement `resolve_direct(store, text)` and optional Main state, cache invalidation, and execution composition. Run Python tests.
2. **Preview** (`api/routes.py`, `tests/test_api.py`): test legacy and direct preview including ordering and invalid inputs; pass validated state through the shared resolver. Run Python tests.
3. **Controls and workflow restoration** (`web/index.js`, JavaScript tests): test adding, selecting, ordering, deletion, Snapshot transitions, restoration and stale responses; implement controls for both Main nodes and send current state to preview. Run Node tests.
4. **Documentation and verification** (`README.md`, `README.en.md`, `CHANGELOG.md`): document behavior and limitations; run all checks in AGENTS.md, review the diff and report unverified ComfyUI browser checks.
